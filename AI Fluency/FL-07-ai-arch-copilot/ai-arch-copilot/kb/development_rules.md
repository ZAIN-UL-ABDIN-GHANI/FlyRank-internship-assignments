# Development Rules

## General
- Build a working MVP, not a perfect enterprise system.
- Keep responses concise. Prefer working code over long explanations.
- Build incrementally. Finish one feature before starting another.
- Never redesign the entire project unless requested.

## Coding
- Write clean, modular code. Follow SOLID principles where reasonable.
- Avoid overengineering and premature optimization.
- Reuse existing code whenever possible. Remove dead code.
- Keep functions small and readable. Use meaningful variable names.

## Project Structure
- Keep folders organized. Do not create unnecessary or placeholder files.
- Create files only when they provide immediate value.

## Dependencies
- Use the minimum number of dependencies. Prefer standard libraries when possible.
- Do not introduce new frameworks without justification.

## Error Handling
- Handle expected errors gracefully. Provide useful error messages.
- Never silently ignore exceptions.

## Approval and Scope
- Never implement features that were not approved or defined in the spec.
- Before implementing a major feature, briefly describe the plan first.
- Wait for approval before continuing when the user requires it.

## Documentation
- Do not create documentation unless requested.
- Keep all documentation short and practical, under 1-2 pages.
- Avoid large architecture documents, unnecessary diagrams, or multiple versions of the same document.
