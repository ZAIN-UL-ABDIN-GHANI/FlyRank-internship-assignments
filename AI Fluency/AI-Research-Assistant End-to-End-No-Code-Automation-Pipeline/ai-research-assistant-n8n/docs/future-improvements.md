# Future Improvements

| Improvement | Description | Why not in v1 |
|---|---|---|
| **Scheduled execution** | Replace Manual Trigger with a Schedule Trigger node so recurring topics run automatically (e.g., weekly), with topics stored in a Google Sheet the workflow reads from | v1 intentionally starts manual so every run has a clear human-initiated moment; scheduling is a natural next step once the manual pipeline is trusted |
| **Slack integration** | Post the report link and executive summary to a Slack channel in addition to (or instead of) email, and route Quality-Review-FAIL reports to a dedicated review channel | Keeps v1's dependency surface minimal (Google + one LLM + one Search API); Slack adds a 5th external integration |
| **Notion integration** | File reports into a Notion database instead of / in addition to Google Drive, enabling richer tagging, search, and a browsable report archive | Google Drive was chosen for v1 as the simplest, most universally available option; Notion requires an additional account/API setup |
| **Vector database + RAG** | Store all past reports in a vector database (e.g., Pinecone, Weaviate) so new runs can check "have we researched this before, and what changed?" | Adds meaningful infrastructure and cost; only worth it once report volume is high enough that duplicate research is a real problem |
| **Multi-agent workflow** | Split the single LLM Summarizer role into specialized sub-agents (a "fact-checker" agent that cross-verifies numeric claims, a "tone" agent for audience-specific rewrites) | Adds orchestration complexity; v1's single Quality Review pass already catches the highest-value share of issues at much lower cost |
| **Source allow-list** | Maintain a curated list of high-credibility domains per topic category to reduce noise from SEO-driven aggregator sites (a recurring issue in `docs/testing.md`) | Requires building and maintaining the list; v1 relies on the Search API's own ranking plus LLM-based triage |
| **Per-audience report styles** | A style parameter (executive-brief vs. analyst-depth vs. plain-language) so one workflow serves multiple audiences without maintaining separate copies | Not needed until the workflow has more than one real audience in practice |
| **Automated secondary fact-check pass** | An independent LLM call (ideally a different provider/model than the primary summarizer) specifically re-verifying numeric claims before filing | Adds latency and cost; recommended once the workflow is used for anything externally distributed, not just internal research |
